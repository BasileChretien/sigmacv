# archiving

The self-archiving programme: help the owner put a legal copy of each closed paper in the right open repository. **Editor-only, end to end** — nothing here reaches the public page, an export, the OAI-PMH feed, a frozen version or the anonymous preview (`tests/funders-not-public.test.ts` checks it at the source).

## Why one folder

The worklist prints three separate facts under a closed work, each with its own source and date: the **publisher's** policy (OA.Works), the **statute** of the country printed on the paper, and the **funder's** policy (`funders/oaPolicies.ts`, joined to the owner's own grants). They must never merge into one verdict. This folder holds the first two and the deposit routes, so the programme reads in one place while `funders/` stays about funders:

- `selfArchivingPass.ts` — the OWNER sync's OA.Works pass (`meta.selfArchiving`). Called from `syncCvForUser` only, never from `buildCvFromOrcid` (which the anonymous preview shares). Sequential, capped, wall-clock budgeted, a 7-day refresh window; a failed call keeps the stored record and stamps the ATTEMPT only (`meta.selfArchivingTriedAt`), so a DOI that times out queues behind the works never examined instead of holding the head of the rotation; an answered "no record" clears it. The HTTP client itself follows the external-client convention at `src/lib/oaworks/client.ts`.
- `statutoryRights.ts` — the committed, hand-verified table of statutory self-archiving rules by country (same `verifiedBy` / `lastVerified` scheme as the funder table). Maintainer note: `docs/STATUTORY-ARCHIVING-RIGHTS.md`.
- `repositoryCopiesPass.ts` — the OWNER sync's repository-copies pass (`meta.repositoryCopies`): per journal article with a DOI in either list (closed, or open at the publisher only), closed first, HAL for EVERY work due, then Europe PMC → OpenAIRE → Zenodo for the works HAL did not settle (`src/lib/repositoryCopies/`), stopping at the first copy WITH a file; stored source by source (a failed or unreached source keeps what it said), answered = a file or every source; same rotation, budget, attempt/answer stamps and fail-soft rule as the OA.Works pass. A file anywhere = the paper is open in a repository (`inRepositoryAlready`, out of both lists); a HAL notice without a file redirects the HAL route to the notice (`DepositRoute.notice`: "add the file to hal-…").
- `depositNow.ts` — which closed journal articles the owner can deposit TODAY, and on what ground: the publisher's recorded permission with its embargo over (the record's end date, or its duration from the work's date filled to the END of what is known), or a statutory author right whose `delayMonths` has run — the accepted manuscript, whatever the record says. The worklist's first list is these rows and no other; `depositChips.ts` reads the same list, so a chip and its row never disagree. A second list, folded on every visit (`depositElsewhereRows`), holds the journal articles already open AT THE PUBLISHER (gold, hybrid, diamond, bronze — never green, whose copy is in a repository already) that a ground lets the owner put in a repository too: the work's own CC licence first (`basis: "licence"` → the published version, the licence in the form note), else the record, else a right that has run; no chip for these; `rightsSentences.ts` `depositNowLine` says the ground in one sentence under the action.
- `depositRoutes.ts` — one action per closed journal article (verb + destination link + one-clause reason) and the other places. Pure, from stored fields, the committed tables and the owner's funder crosswalk. The ORDER is the rule, never a score: a confirmed funder repository for a funder the work names → HAL, Zenodo or arXiv where OpenAlex lists the owner's works → the national repository of the affiliation country (the paper's, or the owner's current one when they choose it) → the owner's other repositories (after the national rule: a co-author's institutional repository reaches that list too) → Zenodo. A destination an earlier rule reached is not repeated. **The action's words never go beyond the OA.Works record** (`depositAction`: the version it allows; "only if your publishing agreement allows it" when it allows no deposit or names only other kinds of place, `placeFitsLocations`), and the record's licence and running embargo travel to the form (`depositNotes`). Rendered by `src/components/WorklistDeposit.tsx`.
- `repositoryDirectory.ts` — the committed tables behind the routes: known deposit forms (HAL, Zenodo, arXiv), OpenAlex `repository` sources that take no author deposit of a published paper (indexes, aggregators, data platforms, preprint servers), how each kind of place reads OA.Works' location vocabulary, national repositories by country, funder repositories by FundRef DOI. Same `verifiedBy` / `lastVerified` scheme; an unconfirmed destination is recorded and **never routed to**. Maintainer note: `docs/DEPOSIT-ROUTES.md`.
- `depositRepositoriesPass.ts` — the OWNER sync's repository pass (`owner.depositRepositories`), two polite-pool OpenAlex calls sharing an 8-second budget (`src/lib/openalex/repositories.ts`), a 7-day refresh window (`freshness.ts`, shared with the OA.Works pass), fail-soft the same way. Called from `syncCvForUser` only.
- `currentAffiliation.ts` — the country of the owner's current affiliation, read from the `Institution` table by the `/cv` page for the "suggest places by your current affiliation" choice.

## Rules (test-enforced)

- **Facts beside the work, never a state.** No totals, no N-of-M, no percentage, no "coverage", no verdict. Whether a policy or a statute applies is the owner's judgement; statutory sentences say "may also apply".
- **Banned vocabulary** on every `wl*` key in all ten locales and in the statutory table: compliant / compliance / overdue / violation / mandate / mandatory / percent / %, and their translations (`tests/worklist-i18n.test.ts`, `tests/funding-i18n.test.ts`, `tests/statutory-rights.test.ts`).
- **Every fact is dated and sourced**: OA.Works' own "updated" date plus SigmaCV's retrieval date; each statutory entry's `lastVerified` (or the pending wording).
- **Store only what the row prints.** The OA.Works boundary drops copyright-owner names, contributor e-mails and scores; a work that stops being a candidate loses its record. The repository pass stores names and links, never the work counts that ordered them.
- **Analytics carry the route's kind only.** A click on a deposit link sends the cookieless `Deposit route` event with `{ kind }` (`funder` / `own` / `national` / `zenodo` / `shareyourpaper`) — never the DOI, the destination or anything about the person (`tests/worklist-deposit-panel.test.tsx`).
