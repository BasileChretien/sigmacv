# External data sources

> Maintainer reference, moved out of the root `CLAUDE.md` (which keeps the matching rule, the editor-only rule and the Open Policy Finder terms as one-line rules). One entry per source: what it supplies, how it is matched, and its terms.

All external clients live under `src/lib/<source>/`, send a polite-pool `mailto`/User-Agent, go through `http.ts`, and are **fail-soft** (a hiccup never breaks a sync). The matching rule is load-bearing: **identifier-matched** outputs (ORCID/DOI) auto-include; **name+org-matched** outputs (registries/funders with no ORCID) are **review candidates** — built `included:false` with `meta.reviewFlag="name-matched"`, surfaced with a review badge, never auto-included (`src/lib/grants/match.ts` `matchesNameAndOrg` returns false with no org → never name-only).

- **OpenAlex API** — free; `mailto` polite pool; publications, metrics, grant fields. The primary works source.
- **ORCID public API** — free, non-commercial; OAuth for authenticated iD + public data. _(Member API / write = deferred, paid.)_
- **Crossref** — bibliographic gap-fill by DOI **and** grants via the Grant Linking System (`fetchCrossrefGrantsByOrcid`, ORCID-matched).
- **Open Editors Plus** — editorial roles (owner's dataset, Postgres table).
- **DataCite** + **OpenAIRE** — datasets & software (ORCID-matched, merged + deduped by DOI). OpenAIRE uses a cached refresh-token (`OPENAIRE_REFRESH_TOKEN`, optional → anonymous).
- **DBLP** — conference papers (SPARQL ORCID→PID→XML, auto-included).
- **UKRI / NIH / NSF** — national funder grants (name+org review candidates; keyless).
- **ClinicalTrials.gov** (v2) + **EU CTIS** (`ctis-public-api`, undocumented) + **WHO ICTRP** — clinical trials (name+org review candidates) into the Clinical Trials section. ICTRP has no live API → a **dormant** `IctrpTrial` table fed by `npm run ictrp:import` (see go-live checklist).
- **EPO OPS** — patents by inventor (OAuth client-credentials `EPO_OPS_KEY`/`SECRET`, XML). Name+org review candidates → Patents section. Dormant without credentials.
- **Wikidata** — owner identity (`wdt:P496` ORCID match) → `owner.wikidataUri`/`wikidataSameAs`, surfaced as `sameAs` in the public JSON-LD (not a CV item).
- **ROR** — institution canonicalization (provenance-only).
- **Jisc Open Policy Finder** API (`api.openpolicyfinder.jisc.ac.uk/retrieve`, ISSN-keyed, key in the `x-api-key` header, `OPEN_POLICY_FINDER_API_KEY`; data CC BY-NC-ND 4.0) — the journal's self-archiving policy, FIRST source of `meta.selfArchiving` (`src/lib/openPolicyFinder/client.ts`: the routes with no fee, no prerequisite and a repository among their places; the record keeps them all with a default — `permissionFor` — and the worklist row picks the one for where it deposits, today — `archiving/policyRoutes.ts`; an open-access journal's record is no record for a closed article). **Terms agreed with Jisc (case CS-00957483, 2026-09-17) — keep them true:** short factual lines shown privately to each researcher in their own editor, credited to Open Policy Finder with a link to the journal's record and the date retrieved; never on a public page, in an export, or redistributed; lookups by ISSN only, for the owner's own closed articles, during their own sync, a journal asked at most once a week (its answer, kept on the owner's records with `meta.selfArchivingOpfAt`, is reused within the week); the owner's own downloads (every export format, RO-Crate, account export) drop the records (`src/lib/cv/licensedPolicies.ts`).
- **OA.Works** permissions API (`bg.api.oa.works/permissions/<doi>`, keyless, public-domain data) — the FALLBACK policy source, for a journal Open Policy Finder has no record of (or when no key is set). Both are stored as `meta.selfArchiving` with their `source`, by the **owner sync only** (`src/lib/archiving/selfArchivingPass.ts`, never the anonymous preview), and shown beside the statutory table (`src/lib/archiving/statutoryRights.ts`, maintainer note `docs/STATUTORY-ARCHIVING-RIGHTS.md`) in the editor worklist, every line naming its source. Editor-only end to end; see `src/lib/archiving/CLAUDE.md`.
- **PubMed E-utilities** (`esummary`, keyless, `tool`/`email` polite params, ≤3 req/s) — for each PubMed-indexed work, the **clinical practice guidelines that cite it**: NIH iCite's clinical citers (`cited_by_clin`) typed through PubMed's publication types (Practice Guideline, Guideline, Consensus Development Conference), stored as `meta.guidelineCitations` by the **owner sync only** (`src/lib/pubmed/guidelineCitationsPass.ts`, never the anonymous preview), shown as a chip on the publication row and named in the starter drafts of the narrative sections. Never rendered on the CV; stripped from every public surface. Two identifier hops (PMID → PMID), no name matching. Partial by construction: a guideline PubMed does not index is not seen, and the chip says so. This is the free part of what Overton indexes; legislation, court decisions and news are not covered.
- **Deposit routes** — each closed journal article in the editor worklist gets ONE deposit action (verb + destination link + one-clause reason), then the other places and ShareYourPaper (`shareyourpaper.org/<doi>`, a link only — no API call). Rule order: a confirmed funder repository → HAL/Zenodo/arXiv where OpenAlex lists the owner's works (`group_by=locations.source.id` over repository-typed sources, two polite-pool calls sharing an 8 s budget, in the **owner sync only**, `src/lib/archiving/depositRepositoriesPass.ts`) → the national repository (FR → HAL) → the owner's other repositories → Zenodo. The action's wording never goes beyond the publisher's record (Open Policy Finder or OA.Works) (`depositAction`: the version it allows, or "only if your publishing agreement allows it"), and the record's licence and running embargo travel to the form (`depositNotes`). Committed tables in `src/lib/archiving/repositoryDirectory.ts` (maintainer note `docs/DEPOSIT-ROUTES.md`); an unconfirmed destination is never routed to. The `Deposit route` analytics event carries `{kind}` only.
