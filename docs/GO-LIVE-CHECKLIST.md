# Production go-live checklist

> Maintainer reference, moved out of the root `CLAUDE.md` (which keeps the rules as one-liners). What every production deploy must have configured, the optional and dormant sources with their import steps, and the maintainer's one-time launch tasks.

The app passed three security audits; the hardening it relies on must be **configured at deploy time**. Full detail + rationale in [`SECURITY.md`](../SECURITY.md). Before opening to real users:

- [ ] **`POSTGRES_PASSWORD`** — set a strong value (`openssl rand -base64 24`). Deployment now _fails fast_ if unset (no committed default).
- [ ] **`AUTH_SECRET`** — ≥ 32 chars (`openssl rand -base64 33`). Enforced in prod by `env.ts`.
- [ ] **`AUTH_URL`** — the canonical **HTTPS** origin (e.g. `https://cv.example.org`). Anchors OAuth callbacks **and** the CSRF same-origin check (which fails closed in prod). Must match the ORCID redirect-URI host.
- [ ] **`ORCID_ENVIRONMENT=production`** + a **production** ORCID app (client id/secret); `OPENALEX_MAILTO` set (polite pool).
- [ ] **`RATE_LIMIT_PERSIST=true`** — durable, cross-instance rate limiting (defaulted on in the compose files).
- [ ] **Open Editors Plus data** — after the DB is migrated, run `npm run oep:import` once with `DATABASE_URL` pointed at the **production** database (run it from a full checkout with `npm install` done — same as `research:export`; `tsx` is a dev dependency, so this is NOT run inside the standalone container). Re-run on each dataset refresh. It loads the editorial-roles reference table (`OepEditorialRole`, ~589k rows from the committed 6.0 MB seed `prisma/seed-data/oep-editorial-roles.ndjson.gz`, across three trust tiers — `scraped` is auto-included, `propagated` and `openalex` are review candidates); without it the Editorial Roles section is simply empty. To rebuild the seed from an updated OEP parquet: `python scripts/oep-build-seed.py` (needs pyarrow). The script ends by printing the edition's collection dates: copy them into `OEP_SNAPSHOT` (`src/lib/oep/snapshot.ts`), because the site tells researchers when the editorial-roles data was collected and that it is refreshed about once a year (Transparency page, editor's Editorial Roles section).
- [ ] **Open Policy Finder (optional)** — set `OPEN_POLICY_FINDER_API_KEY` (SigmaCV's key, issued by Jisc; the compose files pass it through). Without it the owner worklist's publisher policies come from OA.Works alone. The key is sent only as the `x-api-key` header to `api.openpolicyfinder.jisc.ac.uk`; never print it, never put it in a URL. If Jisc ever withdraws the key, UNSET the variable (a refused key keeps the records on screen, as a failed call does): without a key each Open Policy Finder record goes at its work's next due sync.
- [ ] **EPO patents (optional)** — set `EPO_OPS_KEY`/`EPO_OPS_SECRET` from a free OPS app (<https://developers.epo.org>) to enable the Patents section. Without them the EPO client is dormant (OPS has no anonymous access) and Patents stays empty — no other effect.
- [ ] **WHO ICTRP (optional, DORMANT)** — the `IctrpTrial` table is empty by design: WHO's terms forbid redistributing the dataset, so there is **no committed seed**. To enable ICTRP trials: (1) clear the non-commercial / weekly-refresh / attribution use with WHO (`ictrpinfo@who.int`); (2) download the free WHO ICTRP weekly export; (3) convert it to gzip-NDJSON (per `scripts/ictrp-import.ts`); (4) run `npm run ictrp:import <path>` against the **production** `DATABASE_URL` (same checkout caveat as `oep:import`). The importer drops CT.gov/EU rows (already pulled directly) and must be **re-run weekly** to honour WHO's currency term. Empty table = ClinicalTrials.gov + EU CTIS still work; ICTRP just adds nothing.
- [ ] **FORRT replications (optional, DORMANT)** — the `ForrtReplication` table is empty by design: no dataset ships in the repo. To enable replication evidence: (1) download the FReD dataset — the FReD R package itself pulls it from **<https://osf.io/2tbvd/download>** (linked from <https://forrt.org/replication-hub/>); it is an **XLSX workbook**, not a CSV (verified live 2026-09-04: one sheet, ~4,396 rows), so convert it first, e.g. `python -c "import pandas as pd; pd.read_excel('fred.xlsx').to_csv('fred.csv', index=False)"` (needs `pandas` + `openpyxl`) or `soffice --headless --convert-to csv fred.xlsx`; (2) run `npm run forrt:import <path.csv[.gz]>` against the **production** `DATABASE_URL` (same checkout caveat as `oep:import`; the importer rejects a raw XLSX file outright with a clear message rather than silently importing 0 rows — see `scripts/forrt-import.ts`'s module doc comment for the verified header and `COLUMN_CANDIDATES`); (3) **re-run on each FReD refresh** — no fixed cadence is published, but a weekly-to-monthly check against the dataset's changelog (<https://osf.io/fj3xc/download>) is reasonable. Empty table = the feature is a no-op (`display.showReplications` has nothing to show). FReD is CC-BY (citation text at <https://raw.githubusercontent.com/forrtproject/FReD-data/main/output/citation.txt>) — **cite FORRT/FReD** wherever the data is shown or reused; unlike WHO ICTRP, redistribution is allowed by the licence, so a committed seed _could_ ship in future — none does yet.
- [ ] **Postgres stays unpublished** to the internet — compose uses `expose` only; never add a host `ports:` mapping for it.
- [ ] **Caddy** overwrites `X-Forwarded-For` with the real peer + sets `request_body max_size`, 404s `/api/internal/*`, and 405s any method the app never serves (TRACE/TRACK/CONNECT/…) (already in `Caddyfile` — don't remove).
- [ ] **Container** runs non-root with `cap_drop: ALL` + `no-new-privileges` (already in the Dockerfile + compose).
- [ ] **Research logging: approved, switch still OFF until the consent panel is deployed.** Nagoya University's Bioethics Review Committee approved the observational study on 2026-10-21 as **試験番号 2026-0310** (研究計画書 第1.2版; 説明書/同意書 第1.1版 in Japanese; Information Sheet/Consent Form Version 1.0 in English; 別添1, the consent-screen specification). The research panel that implements 別添1 (consent version 2, `src/lib/research/consent/`) is the only way in: set `RESEARCH_LOGGING_ENABLED=true` once it is live in production, never before. The consent text exists in Japanese and English only (`APPROVED_CONSENT_LOCALES`); the other eight languages wait for an approved amendment. The **research export stays gated** (`RESEARCH_EXPORT_*`) until its de-identified fields are finalised against the pre-registration.
- [ ] **Upstream OpenAlex curation stays OFF** (`OPENALEX_CURATION_ENABLED` unset) — the "not mine" push (`src/lib/openalex/assert.ts`, endpoint `/api/cv/assert`) is disabled-by-default v2 scaffolding that makes **no** network call while unset; keep it off until the real OpenAlex curation API contract is confirmed and the **PROVISIONAL** payload finalised.
- [ ] **Narrative AI drafting — BRING-YOUR-OWN-KEY, nothing to configure.** The server holds **no** key and presets **no** provider (`src/lib/ai/*`, endpoint `/api/cv/narrative-draft`); each logged-in user enters their own OpenAI-compatible endpoint + model + key in the editor, kept only in their browser. The route is a stateless, **SSRF-hardened** relay (https-only; refuses private/loopback/link-local/metadata hosts) that forwards one call and stores/logs nothing (no key, no prompt). Off by default per-user (no key = no button), consented per-use, disclosed in the privacy notice. No AI_* env exists — nothing to set at deploy.
- [ ] **Objection route (`/object`) — register the second ORCID redirect URI.** The self-service GDPR Art. 21 route verifies an iD through a second Auth.js provider id (`orcid-object`, same ORCID app) whose callback is `https://cv.example.org/api/auth/callback/orcid-object`. Add that URI to the **production** ORCID app's redirect URIs (and the sandbox app's for dev, with the dev origin); until it is registered ORCID answers `redirect_uri` mismatch on /object and nothing else is affected. Needs `PREVIEW_SUPPRESSION_KEY` (set 2026-09-09); without it /object/done says objections are unavailable and the email route applies.
- [ ] **Preview analytics claim** — the privacy notice says analytics never record which ORCID iD was previewed. (The same scrub keeps only the origin of an outbound-link URL: outbound-link tracking is ON in the site's Plausible config, verified in the live `pa-*.js` on 2026-09-15, and would otherwise send a clicked DOI or ORCID iD. It also replaces an iD anywhere else in a pageview's URL or referrer with `_`, by shape (hyphenated, unhyphenated, or with a percent-encoded hyphen, dash, minus sign or space), together with the whole run of digits it stands in: a 404 is counted like any page, and a mistyped address can hold one.) That rests on (a) the client-side scrub in `src/lib/analytics/plausibleInit.ts` (verified 2026-09-09 against the live `pa-*.js` tracker: `transformRequest` is read from the init options) and (b) the idempotent ClickHouse purge `scripts/deploy.sh` runs on every deploy. After any Plausible upgrade, open a preview and confirm the outgoing `POST …/api/event` body carries `/preview/_`, not an iD. `PREVIEW_SUPPRESSED_ORCID_HMACS` (the Art. 21 objection list) is keyed by the dedicated `PREVIEW_SUPPRESSION_KEY` (required whenever the list is set; `env.ts` fails loudly otherwise) — `AUTH_SECRET` rotation does not touch it; rotating the key means recomputing every entry.
- [ ] **Accepted residuals** (documented in `SECURITY.md`): ORCID has no PKCE (upstream); DB session token at rest (rely on Neon/Postgres encryption-at-rest); revisit if the threat model changes.

Generate secrets with `openssl rand`, put them in the server's `.env` only (never commit), and keep `.env.production.example` as the template.
